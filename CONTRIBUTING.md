# Правила разработки

## Ветвление

Используем GitHub.

Основные ветки:

- main - стабильная версия проекта;
- develop - ветка интеграции.

Для разработки используются ветки:

feature/IC-01_<роль>_initial_setup

Пример:

feature/IC-01_backend_initial_setup

## Conventional Commits

Формат коммита:

<тип>(<область>): <краткое описание>

Примеры:

feat(api): add health endpoint

## Pull Request

Каждый участник:

1. Создаёт отдельную feature-ветку.
2. Выполняет необходимые изменения.
3. Создаёт коммит.
4. Отправляет ветку в GitHub.
5. Создаёт Pull Request в develop.
6. Добавляет ссылку на задачу.
7. Добавляет описание выполненной работы.
8. Добавляет скриншот результата.
9. Назначает Team Lead ревьюером.

## Code Review

Team Lead проверяет:

- название ветки;
- название коммита;
- описание Pull Request;
- соответствие задания;
- работоспособность изменений.

При обнаружении ошибок Team Lead оставляет комментарий.
Автор исправляет замечания.

После успешного Code Review Team Lead одобряет
Pull Request и выполняет Merge в develop.
