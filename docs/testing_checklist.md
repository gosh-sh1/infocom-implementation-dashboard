# Чек-лист тестирования API

## Позитивные сценарии:

1. [x] **Создание проекта**: POST `/api/projects` с телом `{"title": "Новый проект"}`. Ожидается: статус 200, проект добавлен в БД.
2. [x] **Получение проектов**: GET `/api/projects`. Ожидается: статус 200, JSON-массив с проектами.
3. [x] **Создание задачи**: POST `/api/tasks` с телом `{"title": "Сделать ТЗ", "project_id": 1}`. Ожидается: статус 200, задача создана.

## Негативные сценарии:

1. [x] **Создание задачи без названия**: POST `/api/tasks` с пустым `title`. Ожидается: ошибка 422 (Unprocessable Entity).
2. [x] **Создание задачи для несуществующего проекта**: POST `/api/tasks` с `project_id: 9999`. Ожидается: ошибка базы данных (сбой ограничения внешнего ключа) или 404.

## Бизнес-логика (автоматический статус):

1. [x] **Блокировка проекта**: создать задачу со статусом `"Blocker"` для проекта `id=1`. Ожидается: при следующем GET `/api/projects` статус проекта `id=1` изменится на `"Blocked"`.
